BeeOS 通过一套任务模型暴露三种 Android 运行时：

| 运行时 | 运行位置 | 任务入口 | 原子 `/mobile` 控制 |
| --- | --- | --- | --- |
| Device Agent | 宿主机 ADB 连接的手机 | WebChat、OpenAPI、A2A、MCP | 支持 |
| BeeRunner | 手机上的无障碍应用 | WebChat、OpenAPI、A2A、MCP | 暂不支持，请提交任务 |
| Redroid | BeeOS 托管 Android 容器 | WebChat、OpenAPI、A2A、MCP | 支持 |

WebChat 和所有公开任务入口都以 Message Service 为持久化事实源。ACP
继续服务于兼容的 Device Agent 实时 session、事件和工具，但它不是第二套任务数据库，
也不是 WebChat 的默认投递通道。

## 十分钟流程

1. 安装并绑定 Device Agent、扫码绑定 BeeRunner，或创建 Redroid 实例。
2. 在 **设置 -> API Keys** 创建 `oag_` 用户 API Key。
3. 找到 Android Instance 及其 Agent。
4. 提交可靠任务并订阅事件。
5. 不再需要结果时，通过任务 API 取消。

```bash
export BEEOS_API_KEY="oag_..."
export BASE="https://openapi.beeos.ai"
export AGENT_ID="<agent-id>"

TASK_ID=$(curl -s -X POST "$BASE/api/v1/agents/$AGENT_ID/tasks" \
  -H "Authorization: Bearer $BEEOS_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: mobile-quickstart-001" \
  -d '{"message":"打开设置","deadline_ms":120000}' | jq -r '.data.task_id')

curl -N "$BASE/api/v1/agents/$AGENT_ID/tasks/$TASK_ID/events" \
  -H "Authorization: Bearer $BEEOS_API_KEY"
```

请求被接受后，即使调用方断线，任务也会继续可靠执行。用同一个 idempotency key
重试不会创建第二个手机任务。

## Device Agent 模式与模型

观察模式与执行模式是独立参数：

| 参数 | 可选值 | 默认 |
| --- | --- | --- |
| `observation_mode` | `auto`、`structure`、`vision` | `auto` |
| `execution_mode` | `flash`、`pro` | `flash` |

Flash 使用选定模型的适配器直接执行；Pro 增加规划、基于实时页面的操作、
动作校验与原始任务要求的最终核对。兼容旧值：`fast -> flash`，
`reasoning/advanced -> pro`，观察模式 `xml -> structure`。
这些调整仅针对 Device Agent，BeeRunner/Portal 保持原样；
旧版 Redroid sidecar 可能需要升级后才能使用新模式。

Web 始终提供 **Default model**。不传 `model` 即使用设备配置中的默认模型，
旧 `auto` 仍兼容。显式传入模型 ID 时复用设备现有 URL/API Key。
Device Agent 的 `models/list` 是推荐目录，不是白名单；外部调用仍可传自定义模型。
目录中有模型不代表当前服务商一定支持它。Pro 要求兼容原生工具调用的通用模型，
专用 GUI 适配器仍用于 Flash。Planner/Checker 可由运行时另行配置模型。

现有 Python SDK 可通过任务 metadata 传参，不需要重新生成 SDK：

```python
import os
import beeos_sdk

configuration = beeos_sdk.Configuration(
    host="https://openapi.beeos.ai",
    access_token=os.environ["BEEOS_API_KEY"],
)
with beeos_sdk.ApiClient(configuration) as client:
    response = beeos_sdk.TasksApi(client).create_task(
        agent_id=os.environ["BEEOS_AGENT_ID"],
        create_task_request=beeos_sdk.CreateTaskRequest(
            message="Open Settings, then return home without changing settings.",
            deadline_ms=180000,
            idempotency_key="device-pro-example-001",
            metadata={"observation_mode": "auto", "execution_mode": "pro"},
        ),
    )
    print(response)
```

直接执行改用 `execution_mode=flash`。仅需覆盖默认模型时才在 metadata 中添加
`model`。任务已接受不等于成功，应等待终态并检查原因和动作回执。
规划与最终核对阶段可能暂时没有正文，不能仅因文本暂停就认定超时；
应使用任务 deadline 和取消接口。

## 单写入规则

同一台手机同一时间只安全执行一个会改变设备状态的任务。BeeOS 在 WebChat、
OpenAPI、A2A、MCP 和原子控制之间共用设备级 lease：

- 第二个写入请求立即返回 `device_busy`，不会被隐藏排队。
- OpenAPI 原子调用返回 HTTP `409` 和 `device_busy`。
- A2A 投影为 `rejected`，reason 为 `device_busy`。
- MCP 返回包含 `device_busy` 的结构化工具错误。
- 截图、UI Tree、应用列表和被动实时画面可与当前写任务并存。

只有活动任务进入终态后才能重试；新的用户意图应使用新的 idempotency key。

## 任务状态

```text
queued -> running -> completed
                  -> failed
                  -> cancelled
queued ----------> cancelled
```

`input_required` 和 `auth_required` 是可恢复暂停态。超时表示为
`failed + reason=timeout`。结果不确定表示为
`failed + outcomeCertainty=uncertain`，不能自动重放，因为动作可能已经到达手机。

协议适配器可以使用各自的标准 wire 状态。例如 A2A 使用 `working`、
`completed` 和 `rejected`，BeeOS 产品投影保持上述统一语义。

## 原子控制

Device Agent 和 Redroid 可通过 `GET /api/v1/instances/{id}/mobile`
读取实时屏幕尺寸和能力。v1 安全面包括：

```text
screenshot, ui_tree, list_apps
tap, double_tap, long_press, drag, swipe, scroll
type, key, press_button, open_app
```

每个端点只映射到固定 allow-list 工具，不允许传入任意 MCP 工具名。安装/卸载应用、
shell 和高权限系统设置不属于 v1。BeeRunner 的直接控制适配尚未接入，因此会返回
`action_unsupported`，应使用任务入口。
